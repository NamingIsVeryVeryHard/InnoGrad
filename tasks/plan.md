# 第一周交付与验收

第一周完成项目问题定义、产品描述、仓库说明和基础协作流程。任务通过 [GitHub Issues](https://github.com/NamingIsVeryVeryHard/InnoGrad/issues) 跟踪。

## 交付内容

| 任务 | 交付内容 | 验收标准 |
| --- | --- | --- |
| [#1 定义工程问题](https://github.com/NamingIsVeryVeryHard/InnoGrad/issues/1) | [5W1H 与产品描述](../docs/requirements/problem_definition.md)、[产品范围](../docs/requirements/product_scope.md) | 问题、用户、价值与衡量方式清楚，四项核心功能、学生端与管理端职责及业务边界清楚，事实与假设有明确区分 |
| [#2 完善项目 README](https://github.com/NamingIsVeryVeryHard/InnoGrad/issues/2) | [README](../README.md) | 首次访问者能了解项目背景、目标用户、功能规划和当前状态，并找到详细文档 |
| [#3 建立基础项目管理流程](https://github.com/NamingIsVeryVeryHard/InnoGrad/issues/3) | [协作流程](../docs/mgmt/project_workflow.md)、[Issue 模板](../.github/ISSUE_TEMPLATE/)、[PR 模板](../.github/PULL_REQUEST_TEMPLATE.md)及 Project | 当前任务能在看板中跟踪，Team planning 和 Bug tracker 有明确用途和入口 |

问题定义与产品范围确定后，同步更新 README。看板视图与任务状态保存在 [InnoGrad Project](https://github.com/orgs/NamingIsVeryVeryHard/projects/1) 中。
