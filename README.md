# InnoGrad · 研究生全周期智能审核与成长管理系统

**所属展示机构：上海智能教育研究院**  
**当前代码版本：v0.3.0**  
**文档更新：2026-11-02**  
**当前状态：可运行的本地开发与业务验证系统，尚未完成学校生产上线验收。**

InnoGrad 用于把研究生的培养任务、年度报告、论文成果、证明材料、审核记录和成长画像连接起来。学生在系统中持续记录研究进展，Agent 按规则检查材料，正常通过后由后台自动归档并更新画像；材料内容缺失或不符时先退回学生补正；系统异常由授权教师或机构处理。

目前已实现的核心业务范围是 **论文成果登记与年度培养报告**。开题、中期、毕业和学位申请等完整培养环节属于后续扩展范围。“全周期”是项目建设目标，不代表这些环节已全部实现。

## 1. 这份代码用来做什么

### 1.1 面向的实际工作

- **学生材料填报**：登记论文、填写研究进展、上传原件、保存草稿、提交与补正。
- **培养任务组织**：发布年度任务，明确材料要求、截止日期、应交名单及审核责任。
- **Agent 材料审核**：组织本次提交的表单、原件文本与规则，获取可追溯的检查结果。
- **异常处理与归档**：正常通过自动归档；异常转交机构；更正期间保留旧有效档案。
- **研究成长记录**：汇总已归档事实，关联研究目标、里程碑、个人贡献、反馈和反思。
- **培养支持与预警**：发现未交、临期、退回、审核异常和计划逾期事项，跟进后记录处理过程。
- **过程追溯**：保留提交版本、审核主体、报告、原件哈希和操作日志。

这份代码可以用于本地演示、业务规则讨论、前后端联调、Agent 接口接入和后续开发。已有页面调用真实后端，业务记录保存在数据库，附件保存在服务端目录；关闭浏览器不会清除这些记录。

### 1.2 不应混淆的几个概念

| 概念 | 在本项目中的含义 |
| --- | --- |
| 上传成功 | 文件通过当前上传检查并保存，不等于其内容已核真 |
| 正式提交 | 创建冻结版本，后续补正产生新版本，不覆盖旧版本 |
| Agent 任务完成 | 分析任务结束，不一定表示材料通过；结果可能是不符合或无法判断 |
| 审核通过 | 当前版本满足通过条件，进入后台归档流程 |
| 已归档 | 后台已生成有效档案，并在事务中建立对应画像事实快照 |
| 成长画像 | 当前已确认记录及其材料来源，不是对学生隐性能力的自动测量 |
| 预警 | 需要核对或支持的工作事项，不等于学生能力不足或学业不合格 |
| 模拟数据 | 明确标注的虚构学生和材料；可以真实登录、保存、查询，但不代表真实成果认定 |

## 4. 一份材料如何在系统中流转

### 4.1 正常处理

1. 管理教师发布年度任务，或学生直接创建论文申报。
2. 学生填写表单、上传证明材料，先保存工作稿。
3. 正式提交时，后端校验资格、字段和附件，创建不可直接覆盖的提交版本。
4. 系统创建 Agent 审核任务，Worker 在后台执行原件解析和审核调用。
5. 服务端校验报告、原文引用、附件覆盖、任务状态及版本是否仍有效。
6. 满足当前自动通过条件时，写入 Agent 审核决定及归档事件。
7. Worker 创建档案、切换有效版本并生成画像事实快照。
8. 学生和教师刷新后看到“已归档”，画像来源同步更新。

### 4.2 异常与补正

材料内容存在缺失或矛盾时，先退回学生补正。提示项或允许作为提示的不确定项附提示通过；服务失败、报告或证据校验失败、版本或授权变化进入机构异常队列。学生补正后重新提交，系统创建新版本，原提交和处理意见仍保留。

已归档材料需要更正时，通过更正申请或论文进展更新重开工作稿。新版本正式归档前，旧有效档案不会被删除或覆盖。

过期、取消、被新任务替代或属于旧提交版本的结果，不应触发当前材料归档。系统已有相应检查和测试，但仍需补齐审查报告所列的业务规则与生产可靠性工作。

### 4.3 当前 Agent 的实际状态

本分支通过公共 `AgentClient` 接入项目统一部署的 InnoAgent。本机服务地址为 `http://127.0.0.1:3107`，模型配置为 `ecnu/ecnu-qwen-flash`，材料审核使用 `AI_MODE=innoagent` 与 `REVIEW_WORKFLOW=agent`。

接入层和材料审核前端由本分支交付。画像和预警可以复用同一客户端，分别实现自己的 Skill 与业务规则。页面区分基础检查、真实内容审核和历史演示报告。公共层抽取后的本版本尚未按最终代码运行测试或浏览器验收。

交接文档：[统一接入接口](docs/InnoAgent统一接入接口.md)、[本轮实现与边界](docs/迭代04%20InnoAgent材料审核接入.md)、[材料审核运行说明](docs/InnoAgent材料审核运行说明.md)。

## 5. 成长画像与预警的口径

### 5.1 画像展示什么

画像按以下六类材料观察方向组织证据：

1. 年度目标。
2. 科研训练。
3. 课题与贡献。
4. 教育契合。
5. 学术交流。
6. 实践落地。

雷达图显示的是**可追溯来源条数**，不是能力得分。相同版本、字段及引用文字去重；材料更正后，历史版本仍可查看，但不继续计入当前有效覆盖。

教师关联“材料观察”时，必须引用该学生已归档表单字段中的原文。研究目标、计划、反思和反馈与正式归档成果分开保存。

这六类观察方向不替代历史八维材料初评，也不等同于隐性能力量表。当前不生成学生综合排名或自动能力等级。归档月份分布只表示记录时间，不直接解释为能力成长曲线。

### 5.2 自动预警有哪些

| 类型 | 触发依据 | 条件消除的典型方式 |
| --- | --- | --- |
| 年度材料逾期 | 截止时间已过，仍没有正式提交 | 完成正式提交 |
| 临近截止 | 未来 7 天内截止，仍没有正式提交 | 完成正式提交，或任务条件变化 |
| 材料需要补充 | 材料被退回或重开 | 补充后重新提交 |
| 审核异常 | 当前版本最新 Agent 任务异常、无法判断、失败或取消 | 完成异常处理或新的有效审核 |
| 研究计划需要跟进 | 明确填写的计划日期已过，仍为计划中 | 记录完成或调整计划日期 |

预警依据实时业务状态计算，已有跟进记录持久化到数据库。学生与授权教师都能查看相关跟进内容，教师负责自动预警的处理状态。Agent 服务未配置不会被解释为学生的问题。

预警“再次发生”的事件划分、无跟进事项的完整消除历史等仍需完善，见后文的已知问题。

## 8. 日常启动：已有这个工作区时

如果你正在使用已经配置好的本机项目，**不需要再次初始化账号或重新导入模拟数据**。

最方便的方法是在访达中双击：

[frontend/prototype/启动原型.command](frontend/prototype/启动原型.command)

启动器会检查已有本地服务；需要新启动时执行数据库升级，并启动 API 和 Worker。如果 API 已运行、Worker 无近期心跳，会尝试补启动 Worker。

也可以在仓库根目录打开终端，执行：

```bash
cd backend
../.venv/bin/python -m app.run_local
```

使用期间保持启动终端开启。通过该终端新启动的进程可用 `Ctrl+C` 停止；已有独立运行的服务不属于该终端时，需要在其原终端停止。

代码或 Agent 配置发生变化后，应重启相关进程。本项目默认命令没有启用代码热重载。

## 9. 首次安装：新的开发环境

### 9.1 环境要求

- Python：项目声明最低为 3.11；现有锁定依赖在 **Python 3.14 / macOS** 上验证过。
- Node.js：运行前端测试时需要支持 `node --test` 的版本及测试使用的标准 API；日常打开网页不依赖 Node.js 服务。
- 一个可用的浏览器。

其他系统或 Python 版本需要自行确认锁定依赖的兼容性。首次下载依赖需要网络。

### 9.2 安装依赖与建立数据库

以下命令从仓库根目录开始：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.lock.txt
cd backend
../.venv/bin/alembic upgrade head
```

### 9.3 仅在空开发库初始化账号一次

以下命令仍在 `backend` 目录执行。使用不可覆盖重定向，避免误清空已有密码文件：

```bash
(
  umask 077
  set -o noclobber
  ../.venv/bin/python -m app.seed > runtime/demo-accounts.txt
)
```

确认命令成功后再查看生成的账号文件。`app.seed` 遇到已存在的初始账号会拒绝重置密码。若数据库已有账号，不要重复执行；若已有账号的密码文件丢失，应先核对恢复方案，不要通过清空数据库解决。

需要完整演示数据时，再运行第 6 节的 `app.seed_scenarios`。

## 10. Agent 与环境配置

本机配置文件是 `backend/.env`。未显式设置环境变量时，代码默认使用 `AI_MODE=rules` 与 `REVIEW_WORKFLOW=manual`；本工作区当前使用 InnoAgent 工作流。参考模板为 [backend/.env.example](backend/.env.example)。已有 `.env` 时不要直接覆盖，其中可能包含当前配置或密钥。

| 配置项 | 用途 |
| --- | --- |
| `REVIEW_WORKFLOW=agent` | 使用 Agent 自动通过与异常分流流程 |
| `AI_MODE=agent` | 连接实现项目 `/review` 协议的独立 Agent 服务 |
| `AI_MODE=innoagent` | 使用 InnoAgent 原生会话、工作区和工具循环审阅完整材料 |
| `AI_MODE=chat` | 使用兼容 Chat Completions 的模型服务 |
| `AI_MODE=rules` | 仅执行本地解析及规则检查，不调用语言模型 |
| `AI_BASE_URL` | 管理员配置的服务基础地址，不从学生材料读取 |
| `AI_MODEL` | 模型名称；InnoAgent 实际模型及供应商在其服务端配置 |
| `INNOAGENT_TIMEOUT_SECONDS` | 单次原生执行时限 |
| `INNOAGENT_QUEUE_TIMEOUT_SECONDS` | 等待公共客户端调用位置的时限 |
| `AI_API_KEY` | 服务密钥，按实际服务要求配置 |
| `AI_ALLOW_INTERNAL_HTTP=1` | 经确认需要使用内网 HTTP 接口时启用 |
| `DATABASE_URL` | 数据库连接地址；本地默认 SQLite |
| `FILE_ROOT` | 附件根目录；本地默认 `runtime/files` |
| `COOKIE_SECURE=1` | HTTPS 部署时让会话 Cookie 只通过安全连接发送 |

独立 Agent 配置示意：

```dotenv
REVIEW_WORKFLOW=agent
AI_MODE=agent
AI_BASE_URL=https://your-school-agent.example
AI_API_KEY=your-local-secret
```

兼容 Chat Completions 的服务配置示意：

```dotenv
REVIEW_WORKFLOW=agent
AI_MODE=chat
AI_BASE_URL=https://your-school-model.example/v1
AI_MODEL=your-model-name
AI_API_KEY=your-local-secret
```

以上地址和密钥都是占位示例。独立 Agent 需实现 `POST /review`，返回契约要求的检查项和证据引用。协议、返回结构及失败处理见 [AI 接入说明](docs/AI接入说明.md)。

InnoAgent 接入使用完整审核包文件，由 Agent 自主读取全部原文，应用负责校验反馈、追踪和清理。配置与运行边界见 [InnoAgent 材料审核运行说明](docs/InnoAgent材料审核运行说明.md)。

更改配置后重启 API 和 Worker，再在界面检查服务状态并启动／重试审核。`rules` 模式不能当作真实 Agent 语义审核；Agent 工作流也不会因规则结果而伪造模型通过结论。

本地启动默认只监听本机 HTTP。正式 HTTPS 部署、网络边界、认证与存储需要按上线方案单独配置。若使用自定义数据库，执行迁移和备份时必须确保进程使用同一连接配置；当前 Alembic 连接读取进程环境，不应假定它会自动加载 `.env`。

## 11. 数据保存位置、备份与迁移

### 11.1 默认保存位置

| 路径 | 内容 |
| --- | --- |
| `backend/runtime/development.db` | SQLite 业务数据库 |
| `backend/runtime/files/` | 上传附件及合成演示原件 |
| `backend/runtime/demo-accounts.txt` | 初始示例账号密码 |
| `backend/runtime/simulation-cohort-v1/accounts.json` | 批量模拟学生账号密码 |
| `backend/runtime/simulation-cohort-v1/manifest.json` | 模拟数据批次、学生和来源标识 |
| `backend/runtime/backups/` | 本地备份目录 |
| `backend/.env` | 本机环境与模型服务配置 |
| `output/` | 设计文档、报告、截图等交付产物 |

所有后端命令按本文从 `backend` 目录运行，避免相对路径指向另一份数据库或文件目录。开发库使用 SQLite WAL 时，还可能出现 `development.db-wal` 和 `development.db-shm` 文件；运行期间不要只复制单个数据库文件当作完整备份。

### 11.2 创建备份与验证恢复

在 `backend` 目录执行，目标目录必须不存在：

```bash
../.venv/bin/python -m app.backup create --destination runtime/backups/manual-check
../.venv/bin/python -m app.backup restore --bundle runtime/backups/manual-check --destination runtime/restore-check
```

再次备份时使用新的目录名。备份工具保存数据库和数据库引用的附件，并校验哈希。恢复命令只写入新的隔离目录，不会替换正在运行的数据库。

**该备份包不包含 `.env`、明文初始密码文件和整个 `output` 目录**，这些文件需要按实际需要单独妥善保存。生产 PostgreSQL／对象存储恢复仍需单独设计与演练。

### 11.3 把项目移动到其他位置

移动时应整体保留代码、`backend/runtime`、`.env` 及需要的 `output` 文件。`.venv` 可能含绝对路径，移动后通常应重新创建虚拟环境并安装依赖。新位置下先检查数据库、附件根目录和启动入口，再运行服务。

无需为了“保存”额外迁移：当前文件和业务数据本来就保存在本地。方便打开时，可以把项目目录加入访达侧边栏，或为启动文件创建桌面替身。

## 13. 常见问题

| 问题 | 核对方法 |
| --- | --- |
| 打不开网页 | 先运行启动器，确认 API 终端没有退出，访问地址为 `http://127.0.0.1:8000/prototype/` |
| 只看到学生入口 | 当前登录的是学生账号；退出后用 `teacher` 或 `manager` 登录同一入口 |
| 学生管理没有新增／导入按钮 | 普通导师只有查看权限，需要使用 `manager` |
| Agent 显示待配置 | 核对 `.env` 中的模式、服务地址及必要模型名，配置后重启两个进程 |
| 显示已通过但没有归档 | 查看系统设置中的 Worker 心跳和 Worker 终端日志；检查是否有持续失败的归档事件 |
| 上传成功但页面没有附件 | 上传后还需保存草稿或正式提交，使附件与工作稿关联 |
| 提示版本已变化 | 其他操作已更新记录；刷新当前记录，核对最新内容后重试 |
| 画像某方向显示“—” | 当前没有关联的有效材料，不是能力零分；查看该方向的来源说明 |
| 某份论文在所选学年不显示 | 检查是否明确标注了周期；未标注学年的档案可在“全部记录”中查看 |
| 导出不能下载 | 检查后台是否生成完成、导出是否过期，以及当前账号是否仍有权限 |
| 模拟学生没有重新恢复到初始状态 | 这是预期行为：重复导入不覆盖已操作的演示进度 |
| 端口 8000 已占用 | 先判断是否已有本项目服务；正常服务可直接复用，不应盲目结束其他进程 |

## 14. 已知限制与后续开发重点

当前应优先处理：

1. **自动通过的业务规则完整性**：原文引用和文件覆盖不能替代完整的必查规则清单，需要按材料类型、培养层次逐项验收。
2. **归档事件失败隔离**：持续失败的最早事件可能阻塞后续归档，需要事件重试上限、退避和失败隔离机制。
3. **真实 Agent 接入及评测**：服务尚待配置；协议模拟测试不等于真实语义审核质量验证。
4. **预警再次触发与完整事件历史**：相同来源再次触发时可能沿用旧关闭状态，需独立的预警事件与发生批次。
5. **查询与刷新性能**：群体画像反复查询、审核队列和前端全量刷新需要批量化、分页及规模测试。
6. **生产能力**：学校统一认证、多重角色、登录限流、生产数据库、对象存储、分布式队列和恢复演练尚未完成。
7. **完整培养业务**：开题、中期、毕业、学位申请，以及专利、竞赛、项目等成果类型尚未形成完整独立流程。
8. **更多输出与通知**：当前主要是 JSON 数据与清单导出；完整附件 ZIP、正式排版报告、邮件／短信通知等仍待完善。

当前支持 PDF 原生文本与 DOCX 段落提取；扫描件和图片 OCR 尚未接入。文件格式特征检查也不等于完整内容安全扫描。

详细发现、代码位置和建议顺序见 [进度审查与完善建议](docs/进度审查与完善建议-20261102.md)。
