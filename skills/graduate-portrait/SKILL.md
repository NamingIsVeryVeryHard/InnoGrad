# 研究生综合画像整合

为 InnoGrad 生成可追溯的个人画像，解释学生研究什么、如何推进、目标怎样变化，以及下一步为什么这样安排。已有显性结果、能力等级、判级理由和证据按原值保留。收到新增报告与上一版研究画像时，更新已有解释并保存变化依据。

## 识别输入

接收同一学生、任务和观察期间的以下内容，支持 Markdown、表格、JSON 或其他可读文本，不要求上游遵循固定字段名：

- **显性评价结果**：已有成果和进度事实、年度表现、基础要求检查、规则版本、来源及复核状态。
- **科研能力与研究素养评价底稿**：按任务证据形成的分项判断、原文引用、量规版本、限制和建议。
- **任务与材料目录**：学生标识、任务、期间、阶段以及来源定位。可访问的学生原文用于打开既有引用，不在整合时新增能力判断。

先分清规则说明与学生结果。只有规则文档时，列出生成画像缺少的输入，不编造学生画像。缺某类结果时可生成部分画像，明确“显性结果待接入”或“科研能力评价待提供”；不得从论文数或年度分数补推能力。需要新的能力评价时，列出缺少的底稿，不在画像整合中补评。

学生身份矛盾时返回 identity_conflict，不合并，也不生成另一位学生的画像。期间或任务不同的结果按 scopes 分开保留；范围未知则注明无法确认同一观察窗口，暂不作综合关联。规则版本不同保持原名、原版本和适用范围，不能擅自用新规则替换历史结果。

记录本次输入快照：调用方提供的快照标识、材料版本、统计截止时间、规则版本、来源状态及变更原因。未知信息保持未知，不用生成时间充当截止时间。材料归档或文档已复核不代表其中每条事实已确认；已有事实确认须能定位具体记录、确认来源与范围，否则仍保留原有自述或待核状态。

明确未授权、撤销或被替代的来源不纳入当前画像依据，说明排除原因。旧显性结果或能力底稿仍依赖这些来源时，暂缓受影响部分并请上游按当前快照重新生成，不擅自删改上游结果。争议内容进入待核事项，不包装成已确认成果；没有其他依据时不生成相关解释。沿用输入中已有的来源有效性与权限状态，不自行确认授权。

## 形成画像

1. **登记来源。** 输入已提供来源目录时复用原编号；否则为实际收到的显性结果和能力底稿登记来源，保留原文件、位置、版本、原始状态与已有证据编号。无法定位的上游结果说明来源缺口，不能补造引用或声称已核查。
2. **保留原有评价。** 显性分数、结果、警示和依据按原值保留；能力项的等级、证据状态、理由和限制同样保留。不得复查上游事实、重新算分或再定级；发现输入间表述不一致时并列注明，不自行裁决。
3. **形成有重点的解释。** 结合当前目标、已有工作和任务条件，归纳研究方向、方法选择和具体表现；相关历史用于解释延续、调整或当前问题，不按固定理论栏目填表。能力项暂缓定级时，仍使用其中有原文支持的观察，不把整份画像写成缺项清单。直接归纳与有限推断分开；推断说明引用如何支持解释及适用范围，不增加能力等级或心理标签。关联两类结果时保留各自来源，不从同时出现推导因果或能力高低。
4. **整理行动。** 合并指向同一问题的重复建议，优先给出至多三项具体动作。已有计划保留原时间与状态。

累计画像保留各任务已经定级的表现。当前报告未覆盖某项，不撤销其他有效材料中的原等级；分别标明“当期表现”和“其他任务已展示的表现”及其阶段、期间、标准与证据。没有当期评价时不推算当期等级，不取最高档代替当前表现。历史原文尚未经过逐项评价时，可提出补评相关材料，不能直接从概览描述生成等级。

## 随报告更新研究画像

收到新增报告和上一版研究画像时，按任务提供的更新 Schema 执行。首次输入先建立研究特征与目标；后续输入在旧画像上更新，不把每次处理当作互不相关的总结。

- 逐项保留、细化或限定已有研究特征，说明新旧证据怎样支持修订。未再提及不表示特征消失；单份方案或重复计划不证明稳定习惯。区分直接呈现的研究内容与跨材料形成的解释，不生成心理或能力等级。
- 当前重点、当前目标和条件以新增报告为准。旧目标只有得到本次材料支持，才能继续作为当前目标；实际资源与计划需求分别写明。
- 对照尚未报告完成的旧目标，说明新材料提供的是计划重述、目标细化、方向不同、进展或完成自述，还是没有报告。未跟进的旧计划继续保留，不自动变成完成、失败或放弃。
- 解释已有特征与本次目标、条件、进展之间的关系，再提出具体指导。已有方案已经解决的设计问题，不重复要求从头设计；建议说明执行、验证或调整的下一步及完成产物。
- 沿用已有特征、目标和引用编号，新增编号由任务程序分配。解释的改变保留前后内容、理由及双方证据；旧画像文字不是新的行为证据。
- 材料的记录日期与工作发生日期分别处理。时间关系未确认时只说明内容对应，不声称某旧计划已在之后落实；不能把新增材料或量规变化当成成长。

## 默认 JSON 输出

默认返回符合 [portrait-overview.schema.json](references/portrait-overview.schema.json) 的裸 JSON 对象，不用 Markdown 或单个字符串包裹全文。调用方提供其他 Schema 时遵循该 Schema。只有明确要求阅读版时才另行渲染 Markdown。

- **student_id、scopes**：保留学生标识及各任务的阶段、期间，未知填 null。年报和开题可出现在同一画像中，各自保留评价范围。
- **status**：有画像为 generated；相同材料且无变化为 unchanged；身份冲突为 identity_conflict；输入不足以生成画像为 missing_input。后两种状态的 overview 各栏目为空，issues 写具体原因。
- **completion**：显性结果和能力评价均具备时为 complete；缺一类结果为 partial；未生成画像为 not_generated。
- **overview**：current_work 保存已有工作；research_plan 保存计划；demonstrated 保存具体表现；attention 保存关注事项；next_steps 保存行动及 completion_evidence；changes 保存相对前版的变化。每项包含 text 和 source_refs，没有内容用空数组。首次生成的 changes 为空。
- **overview.research_features**：保存研究方向、方法特点及目标与已有工作之间的解释。每项含 text、source_refs、basis 和 rationale；basis 为 observed 表示材料归纳，inferred 表示有限推断，rationale 写所引观察与结论的关系。只有缺项记录而没有相关表现时，不据此推断研究特色。旧任务未配置此栏目时，按其 Schema 返回。
- **evaluations**：按 scope_id 保留原有显性结果及全部能力观察项。每项包含 dimension_id、dimension_label、observation、performance_grade、evidence_state、rationale、grading_standard、source_refs 和 suggestion。rationale 保留原有逐条件判级理由，grading_standard 保留适用量规的三档行为标准。不能只保留等级与观察而丢弃判级理由。未接入的显性结果为 null；依据不足时等级为 null。
- **source_records**：统一登记引用编号、scope_id、文件、页码及原句或表单字段。概览和评价复用编号，不把观察项顺序号当成引文编号。
- **issues**：只列影响本次生成的具体输入冲突或错误，无问题用空数组。可选信息缺失用相应字段的 null 表达，不重复列为提醒；运行标识、生成时间和未使用的快照元数据不进入问题清单。

重复输入保留已有画像，changes 为空；不能声称已写入上传记录或业务档案。新增材料时只描述相对上一版的实际变化，不能将已有内容再次写成新增。

沿用每项已有评分尺度。当前科研能力试用量规采用“待改进、达到要求、表现充分”三档，不把它们转换为年度六维的0—3级，也不临时求隐性总分。已有显性规则分数、权重和汇总结果原样合并；需要模型判断的年度观察项按双方确认的任务标准另行评价，不能由概览文字代填。不把其他任务的分类或尺度转换为学生等级。

直接输出画像，不设置必经的教师审批步骤。保留每项稳定编号、量规版本和证据位置，供调用界面打开原文、记录复核或更正意见；已有模型判断与人工意见分别保存。研究特色、具体表现和建议放在对应栏目。学生使用时突出本人指标结果和下一步计划，导师使用时突出依据与指导事项。

只有满足同一标准、可比任务与支持条件的历史评价，才描述有证据的变化；本次缺历史材料时标注未作成长比较。六维年度表现和七领域能力证据各自解释，不合成“综合能力总分”，不自动排名或形成通过、分流、评优、学位决定。

更正、撤销或培养信息变化时，说明可核查的输入差异及受影响部分；缺前次材料就标明无法比较，不把材料补齐或规则变化写成能力成长。发现提取错误时核对原文与解析，原材料错误指明对应位置，判断分歧列明具体依据。校验失败说明本次未生成结果。

## 使用任务提供的 Schema

若调用者提供源记录目录及输出 Schema，只生成所要求的画像概览：每条 text 必须带目录中存在的 source_refs，行动还需 completion_evidence。调用程序负责保留原有评价和渲染证据索引，不再复制或改写整份源结果。

输入含 input_context 时，将其作为快照与文档级状态，不作为逐事实确认。输入中的待处理状态不表示已有人工意见，不据此增加审批步骤。

## 交付前核对

每个分句都须由本条引用覆盖，不能因为其他记录里有该事实就省略引用。检查证据不足不等于没有观测值；材料未提供不等于实际工作未开展或未确定。概览选择代表性表现，不用一串等级代替具体描述，也不重新统计能力项数量；完整状态由底稿展开。引文用原编号复用，避免在概览再次抄写长证据表。

核对事实与引用、推断与理由，保持等级、数值和状态；计划仍写为计划。具体信息缺口在对应事项说明，正文不添加“仅供参考”“待教师复核”等统一提醒。读者应先看懂学生在做什么、已有何种表现和下一步为何这样安排，再展开完整评价。
