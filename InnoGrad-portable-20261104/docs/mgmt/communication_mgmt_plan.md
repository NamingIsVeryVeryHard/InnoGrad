# InnoGrad 项目沟通管理计划

版本：v1.1｜更新：2026-11-12｜状态：组内评审稿

## 1. 目标与范围

确保成员清楚任务分工、接口约定和交付时间，及时解决阻塞并保留讨论结论。本轮围绕论文、年度报告的“提交—核验—补正—归档—画像—预警”流程开展工作。

依据课程[学习注意事项](https://github.com/bettermorn/IntelligentSWEPractice/blob/main/docs/summary.md)，使用 GitHub 管理任务，按功能模块协作。以下安排经组内评审后执行，负责人由小组落实到具体成员，同一成员可兼任多个角色。

## 2. 分工与沟通对象

| 角色 | 主要职责 | 需要沟通的内容 |
| --- | --- | --- |
| 项目负责人 | 统筹需求、进度与课程汇报 | 本周目标、分工、延期和教师反馈 |
| 架构负责人 | 协调跨模块设计 | 接口、数据结构、状态与权限约定 |
| 材料与档案负责人 | 负责提交、补正、附件和归档 | 表单规则、版本关联及联调问题 |
| 智能审核负责人 | 负责解析、模型接入与证据校验 | 审核规则、模型效果及异常处理 |
| 画像与预警负责人 | 负责材料聚合、画像和跟进提醒 | 指标口径、数据来源及预警规则 |
| 测试与交付负责人 | 负责验收、环境和演示准备 | 缺陷、测试结果及交付限制 |

各模块负责人负责本模块从页面、接口到验收的完整场景。项目负责人统一向课程教师汇报、预约讨论；业务流程疑问通过原型走查向导师、管理教师或学生代表核实。

## 3. 沟通安排

| 活动 | 参与人 | 时间 | 输出 |
| --- | --- | --- | --- |
| 每周组会 | 全体成员 | 每周一次，约 30 分钟 | 本周任务、负责人、截止时间和主要风险 |
| 日常进度更新 | 有在办任务的成员 | 工作日结束前 | 在 Issue 更新已完成、下一步和阻塞 |
| 接口评审与联调 | 相关模块、架构及测试负责人 | 接口变更前评审，每周至少联调一次 | 接口约定、联调结果及待修复问题 |
| 课前检查与彩排 | 项目负责人、演示人、测试负责人 | 课前一天 | 固定演示版本、检查主线、准备备用材料 |
| 课堂汇报与教师交流 | 项目负责人及相关成员 | 每次课程，必要时预约 | 原型展示、进展说明、教师反馈及后续任务 |

具体时间由组会确定，联调和复盘可合并进行。汇报按“完成内容—验证证据—存在问题—下周计划”组织。

## 4. 渠道与记录

- **GitHub Issues**：记录任务、缺陷和风险，每项写清负责人、截止时间、验收条件及依赖。
- **GitHub Projects**：按“待开发—开发中—待评审—已完成”跟踪任务，受阻任务单独标记。
- **Pull Request**：说明变更和验证结果，关联 Issue，经其他成员评审后合并。
- **沟通群与会议**：用于快速协调，影响任务或设计的结论在当天回写 Issue 或文档。

会议记录只保留“结论、行动项、负责人、截止时间”。公开仓库和展示使用合成或授权脱敏数据，不上传学生原件、密码和 API 密钥。

## 5. 问题处理与变更

一般问题进入 Issue，在 1 个工作日内确认处理安排。核心任务预计延期超过 1 天或阻塞超过 1 个工作日时，立即通知项目负责人，调整分工、依赖或范围；原负责人无法参与时指定接手人。

涉及越权、数据丢失、错误归档或演示主线不可用时，立即通知项目、模块及测试负责人，先暂停受影响操作或切换备用方案，再排查恢复。风险处理见[风险管理计划](risk_mgmt_plan.md)。

新增需求和接口变更先说明影响，由相关负责人评审后更新任务、文档和验收条件。课程方案疑问集中向教师预约交流；正式业务规则和真实数据使用由相应业务或管理人员确认。

## 6. 课前检查

确认任务已有明确负责人；核心接口、开发环境和样例数据已准备；原型主线经过走查；两份管理计划已组内评审；未完成事项和备用演示材料已说明。检查结果由测试与交付负责人记录。
