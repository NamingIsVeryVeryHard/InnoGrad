总览审核包路由恢复追溯

学校 Agent 接入与材料审核 · Blueprint

每次审核都从一份冻结审核包开始，最后落到一个可追溯状态

系统把材料、规则、Agent 结果和归档动作串成一条受校验的链路。模型负责分析，服务端负责边界和落库。

实现版本 · 2026-11-02 · material-review-2 · InnoAgent 0.7

Boundary

审核包把“当时看到的材料”固定成证据

提交时系统复制文件角色、大小、媒体类型和 SHA-256，并冻结规则版本与规则哈希。后续 Worker 不读取会变化的草稿，只读取这份快照。

冻结内容5类files · roles · hashes · rules · context
运行时 Skill2层local hash + Agent-loaded copy
证据结论1份per rule, with original locator

Decision

结果只走三条路，异常不会伪装成通过

规则检查先于自动决策。合规结果进入归档；缺材料或规则不通过进入整改；证据冲突、限制项或运行时异常进入人工复核。

approved

合规

逐条规则通过，证据可定位，会写入归档 outbox。

returned

需要整改

必需角色缺失或规则失败，生成 correction 并退回。

exception

证据不确定

限制项、冲突或服务异常只进入人工队列。

report

报告可追溯

每条证据带文件 ID、角色、哈希和页码入口。

Recovery

重试和归档隔离，保证坏任务不会卡住整条队列

服务瞬时错误记录错误码、attempt、next_attempt_atretrying
超过尝试上限保留 agent_metadata，转人工复核pending_review
归档失败嵌套保存点回滚当前副作用ARCHIVE_RETRY
其他任务继续领取到期 outboxnot blocked

Traceability

报告把模型结论连回原件，而不是只展示一句“通过”
