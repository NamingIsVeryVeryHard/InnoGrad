# InnoGrad 代码评审记录：材料审核的引文校验

**评审结论（2026-11-25）：本轮修改通过本地回归验证。** 引文能否校正，取决于能否在同一文件中定位到明确的原文，而不是模型给出的文字是否看起来合理。此次评审保留了这条规则，修复了“整批校验拒绝，部分引文却已写回”的不一致。此结论仅针对本次修改，不代替人工签字或整系统上线验收。

## 1. 如何评审

从 [审核入口 `review`](../../backend/app/review_execution.py) 反向核对三层约束：[证据字段与精确引文校验](../../backend/app/agent.py)、[文件角色与规则覆盖校验](../../backend/app/material_rules.py)、[专项回归测试](../../backend/tests/test_review_execution.py)。方法为静态扫描、源码走查和本地自动化测试；未假定有其他同学参与或批准。

## 2. 主要发现与处置

| 发现 | 证据与影响 | 状态 |
|---|---|---|
| 高：错误返回后输入已改变 | 输入两条引文 `AB`、`missing`，同文件原文只有 `A B`。旧实现抛出 `EVIDENCE_INVALID`，但第一条已变成 `A B`。证实的是内存对象改变，没有证据表明错误结果已入库。 | 已修复。先暂存，整批通过再写回；新增失败路径测试。 |
| 中：查找候选与选择候选混在一起 | 旧主函数有 21 个局部变量；很难直接看出“同文件”“原位置优先”“不能任选其一”分别在哪里保证。 | 已拆分。`_matching_quotes` 找原文，`_unique_candidate` 决定是否唯一；保留跨文件与多义拒绝测试。 |
| 中：两个失败入口的异常转换不明确 | 模型输出结构错误与规则/证据校验错误都转换成业务异常，但原来没有显式指定异常原因。 | 两处均已使用显式异常链，未更换业务错误码。 |

## 3. 检查了哪些行为

| 场景 | 判定依据 | 验证结果 |
|---|---|---|
| 漏空格、换行不同或页码填错 | 同文件中能唯一定位时，可恢复原文并记录原值与修正值 | 既有参数化测试通过 |
| 两页均有候选，但其中一页是所报页 | 优先使用所报页；保存原文换行，不凭归一化文本重写引文 | 新测试通过 |
| 原位置无候选，其他页有多个候选；或引文只在另一文件出现 | 不猜测来源，返回 `EVIDENCE_INVALID` | 既有拒绝测试通过 |
| 同批一条可修、一条不可修 | 整批报错，任何一条输入都不能改变 | 新测试重构前失败、重构后通过 |

## 4. 保留问题与后续顺序

- **优先拆分路由注册。** `backend/app/main.py` 的 `create_app` 圈复杂度仍为 99，其中包含嵌套路由定义，不代表单次请求经过 99 个分支。建议先按业务域提取一组路由，再核对路径、鉴权和回归结果，不宜一次改写所有接口。
- **高重复文本的处理成本未实测。** `_matching_quotes` 仍会枚举同一文块里的全部匹配位置。此次验证正确性，没有测量长材料的耗时和内存；优化前应先用重复短引文建立性能基线。
