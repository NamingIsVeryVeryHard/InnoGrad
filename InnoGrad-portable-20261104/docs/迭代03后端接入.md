# 迭代 03 · 研序工作台真实后端接入

日期：2026-11-02。版本：v0.3.0。

工作台地址：<http://127.0.0.1:8000/prototype/>。

## 行为变化

原型取消浏览器生成的演示业务记录、localStorage 和 IndexedDB 存储，以及可任意切换的角色下拉框。登录使用现有业务账号，HttpOnly 会话 Cookie 与 CSRF 校验沿用现有后端。页面仅展示服务端授权返回的数据。

| 页面 | 真实实现 |
| --- | --- |
| 工作概览 | 从授权学生、任务、提交和档案统计数据；15 秒刷新；全局查询范围内记录 |
| 学生管理 | 学生主档查询、培养资料补录、创建账号及指导/管理关系、服务端 CSV 预览和事务导入 |
| 培养任务 | 发布任务、应交名单、复核资格校验、选择冻结规则版本、学生创建年度工作稿、站内提醒 |
| 审核工作台 | 正式提交版本、文件受控下载、真实 AI 作业结果与证据、取消/重跑、审核意见、乐观锁、退回/通过、重分配 |
| 论文成果 | 创建、保存工作稿、投稿/录用/发表状态与对应日期、贡献、服务器附件、正式提交、进展更新 |
| 成果档案 | Worker 归档、有效版本、冻结历史、更正申请/批准/驳回、导出作业及受控下载 |
| 成长画像 | 读取后端不可变事实快照；只统计当前有效档案，证据可追溯 |
| 关注与提醒 | 数据库存储、按学生范围查询、学生/导师跟进、乐观锁避免覆盖 |
| 规则与模板 | 后端保存不可变版本；任务冻结选定规则；提交服务和规则初审均校验配置必填字段 |
| 操作记录 | 服务端审计日志，按本人操作及可访问业务对象范围返回，导出最近 1000 条 |
| 系统设置 | 登录身份、Worker 心跳、AI 配置状态、存储说明、退出登录 |

新建学生账号的初始密码由服务器随机生成，只在创建响应中返回，不写入日志或幂等结果。名单导入先预览，再确认，确认时重新校验学号与导师范围；任一行失败，整个批次回滚。重复确认拒绝执行。

年度报告引用论文时冻结所引用的提交或有效认定版本，未认定论文明确标记。通过后显示“待后台归档”，只有 Worker 提交归档事务后才显示“已归档”。AI 失败不阻断人工复核；界面显示真实失败原因，不伪造成功。

## 启动与登录

双击 `frontend/prototype/启动原型.command`，启动器会升级数据库并同时启动 API 和 Worker；若 API 已运行而 Worker 无近期心跳，会补启动 Worker。保持启动终端开启。

也可以从 `backend` 目录分别运行：

```sh
../.venv/bin/alembic upgrade head
../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 另开终端，仍在 backend 目录
../.venv/bin/python -m app.worker
```

现有 `student1`、`student2`、`teacher`、`manager`、`operator` 账号和密码未重置；初始化凭据仍位于本机受控文件 `backend/runtime/demo-accounts.txt`。账号名称含“演示”，但本次登录、数据库保存、权限控制和文件处理均使用真实后端，不是浏览器模拟。

新导入学生使用学号作为登录账号。切换身份需要退出后重新登录对应账号。

## 当前边界

本轮实现的是现有试点范围内的实际业务闭环，不能等同于学校生产上线验收。

- AI 当前使用服务端规则模式，支持原生 PDF/DOCX 提取；外部/校内模型需配置实际地址及模型名，OCR 尚未配置。
- 画像展示已认定事实和证据，不虚构能力评分、排名或跨年推断。
- 学校 SSO、多重角色、独立成果主档去重、正式组织目录、PostgreSQL/S3/Celery 部署仍按总体技术设计推进。
- 当前学生管理从已有管理范围内选择导师；不新增任意教师或放宽授权。已有学生学号沿用账号标识，培养资料可补录。
- 导入限 100 人/批，归档导出限 100 份/次；归档导出为清单和哈希，不包含附件正文 ZIP。
- 站内提醒是真实保存并向授权用户显示，不外发邮件/短信。
- 保留现有 Starlette/httpx 测试依赖弃用提示；测试通过。
