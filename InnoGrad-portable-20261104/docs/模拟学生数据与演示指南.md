# InnoGrad 模拟学生数据与演示指南

导入基准日期：2026-11-02（Asia/Shanghai）。批次：`innograd-synthetic-cohort-v1`。

本批数据全部为虚构场景，不对应真实学生、学校成果或学业评价。真实 Agent 服务仍待配置，唯一预置的 Agent 异常报告明确标为模拟报告，未调用外部模型。

新学生账号及随机密码：`backend/runtime/simulation-cohort-v1/accounts.json`，文件权限 0600，目录权限 0700，不纳入 Git。
教师继续使用原有 `teacher` / `manager` 账号，显示名称为上海智能教育研究院。原密码未修改。

## 已实际执行的预警闭环

1. 管理教师选择沈书言，打开计划逾期预警，查看来源及已有模拟跟进。
2. 新增跟进记录，保存到数据库。
3. 退出管理账号，使用 `sim_student_06` 登录学生端，只能看到自己的材料与画像。
4. 在“研究里程碑”中，将 `[模拟] 预警演示：补齐研究记录` 标记为“记录完成”。
5. 学生“下一步行动”的待办降为 0；预警中心的“已处理”显示“条件已消除”，两次跟进历史保留。
6. 重新登录管理教师，群体总览中沈书言的待跟进数同步降为 0。

可用唐若溪（`sim_student_12`）继续演示同一流程。若需重演沈书言案例，学生可对该里程碑点击“重新计划”；原截止日期仍已过，预警将重新显示，历史不会被删除。

其他可演示路径：

- 以周沐清登录，从培养任务继续填写已有工作稿，保存并正式提交，逾期“未提交”条件消除；新提交的 Agent 审核仍显示待配置。
- 以许景行或叶清和登录，查看退回意见、补充材料并再次提交，材料补正预警随状态变化消除。
- 以管理教师查看苏以宁的模拟异常报告、原件与审核异常预警。该报告不是真实 Agent 推理结果。

## 可重复生成与验证

运行位置：`backend`。

```sh
../.venv/bin/python -m app.seed_scenarios --as-of 2026-11-02
```

同一批次再次执行返回 `already_loaded`，不会覆盖操作后的状态、复制记录或重置密码。若输出目录与批次标记不一致，脚本拒绝覆盖，便于人工核对。预警由实际时钟计算，临近截止场景会随日期自然变为逾期。

导入前备份：`backend/runtime/backups/before-simulation-cohort-20261102`。

测试覆盖导入数据完整性、全部附件哈希、六方向来源、学年筛选、预警种类与状态、账号登录、跨学生权限、重复运行不变、失败时数据库与文件回滚。相关 13 项后端测试与 8 项前端测试通过。浏览器完成了上述跨账号闭环。
