# Inno-Agent 平台基础与建设边界

InnoGrad 计划依托 Inno-Agent 建设培养业务系统，复用通用智能体能力，并开发培养规则、学生档案和多角色业务流程。

## 应用职责

| 目录 | 职责 |
| --- | --- |
| `apps/web/` | 承载学生端与管理端；重点建设管理端智能审核和培养管理，学生端以简洁入口提供本人材料、进度和反馈；各入口按具体授权呈现功能 |
| `apps/server/` | 管理身份权限、学生档案、培养规则和审核流程，提供业务接口并接入 Inno-Agent |

当前只预留这两个应用目录。审核、画像、规则和提醒等功能作为业务模块逐步实现，应用目录的划分不决定框架、数据库或部署方式。

## 四层能力关系

| 层次 | 职责与建设内容 |
| --- | --- |
| 数据层 | 关联学生信息、培养记录、材料与制度来源，保存材料版本、审核结论和整改过程 |
| 规则层 | 整理规则名称、适用对象、阶段、审核条件、所需材料、判断方式和版本，区分可执行检查与专家评价依据 |
| AI 层 | 基于 Agent + Skills 组织材料解析、规则检查、证据关联与初审意见生成，探索多智能体协作并保留人工复核 |
| 应用层 | 通过学生端和管理端提供业务入口，连接培养节点智能审核、智能审核中心、学生全周期档案与成长画像 |

四层是能力的逻辑划分，学生端和管理端是用户入口，均由上述 Web 应用和业务服务端承载。具体框架、数据接口和智能体接入方式将在工程设计阶段确定。

## 可复用的平台能力

当前尚未在本仓库集成 Inno-Agent，以下能力需要通过实际业务样本验证。

| 平台能力 | 拟用方向 |
| --- | --- |
| 基于 Pi SDK 的智能体运行与工具扩展 | 执行材料处理、规则检查和结果生成流程 |
| 工作区及 Skills | 组织培养节点规则、评价量表和审核流程 |
| PDF、Office、图片等资料入口 | 处理报告、论文、证明及培养制度 |
| 学习者画像、知识 Wiki 和会话记录 | 为培养资料组织、证据检索和成长记录提供基础 |
| 调度与消息渠道 | 支持节点提醒和待办通知 |
| 可替换的模型接口 | 接入适合文档处理、审核与解释的模型 |

## 建设边界

需要区分开源 Inno-Agent 运行时与 InnoSpark 在线平台。开源运行时面向个人场景，其 README 明确不提供多用户并发、账户鉴权和租户隔离；这个限制不能直接推断为 InnoSpark 在线平台没有这些能力。InnoSpark 已有账号与登录态，并通过 Web 页面嵌入 Agent Sandbox；租户隔离机制、部署版本和可复用接口尚待核验。

设计时优先调查 InnoSpark 的账号、会话与沙箱能力能否复用，再确定需要补建的部分。平台登录身份还需映射到 InnoGrad 的学生归属、指导关系、审核分配和正式确认权限；这些业务授权不能仅由登录状态或工作区名称决定。

学生档案、正式审核结论和成长评价由业务服务端管理，保留材料来源、规则版本、复核意见及修改过程。平台的个人记忆与会话记录不能直接替代这些业务记录。

智能体任务应明确业务目的和授权数据范围。个人任务按学生隔离上下文；跨阶段分析、学院汇总与匹配任务仅使用调用者有权访问的数据。服务端检查权限、核验输出并关联任务记录，正式审核结论经有权限的人员复核后保存。上传材料中的指令性文字只作为材料内容处理。

具体接入方式将在工程设计中确定，业务能力以[产品范围](../requirements/product_scope.md)为准。复用平台代码或资源时保留原有许可说明，并记录选用版本。

技术调研与复用验证问题见[技术方案调研](architecture.md)。当前不将 InnoSpark 的租户隔离视为已验证，也不将其视为缺失。
