# 非功能需求

关联任务：[W2-03 功能与非功能需求（#6）](https://github.com/NamingIsVeryVeryHard/InnoGrad/issues/6)。

**状态：需求草案，待确认。** 当前先说明系统的基本质量要求，具体指标在业务规模、使用环境和技术方案确定后补充。

以下要求适用于学生端和管理端。管理端重点支持审核与培养管理，学生端保持操作简洁。相关业务见[功能需求](functional_requirements.md)，角色与数据范围见[角色文档](actors.md)。

## 基本要求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-1 | 性能 | 列表、详情等日常操作应支持正常业务使用；材料解析和 AI 审核等较长任务应显示进度或处理状态。响应时间和容量指标待确认。 |
| NFR-2 | 安全与权限 | 服务端按角色和授权范围控制操作与数据访问。学生只能访问本人获准查看的信息，智能体只能使用当前任务获授权的数据和工具。 |
| NFR-3 | 数据保护 | 学生材料、档案和评价信息按批准用途使用，控制访问和对外传输，避免在日志或公开资料中泄露敏感信息。 |
| NFR-4 | 可靠性 | 提交、审核和归档应保持记录一致，避免重复操作产生重复结果。解析或模型失败时应显示失败状态，并提供后续处理方式；重要数据应可备份和恢复。 |
| NFR-5 | 可追溯性 | 审核意见和正式结论应能追溯到材料、规则版本及处理人员，关键操作和人工修改保留记录。 |
| NFR-6 | AI 辅助质量 | 辅助结果应说明依据、未检查内容和不确定性，正式结论由有权限的人员复核确认。质量评价标准待结合业务样例确定。 |
| NFR-7 | 易用性与兼容性 | 双端清楚呈现待办、缺项、处理状态和下一步操作，学生端保持简洁。浏览器与设备支持范围待确认。 |
| NFR-8 | 可维护性与扩展性 | 系统应便于调整培养节点、规则和模型配置，保留历史记录及其依据；发生故障时应提供便于定位问题的信息。 |

## 待确认内容

- 实际使用人数、数据规模和材料类型，以及相应的性能与容量指标。
- 学校的部署、数据使用和保留要求，以及备份与恢复安排。
- AI 辅助结果的评价样例、质量标准和验收方式。
- 用户的浏览器、设备和使用习惯。

上述内容确认后再补充具体指标与验证方法。当前文档不表示这些要求已经实现或通过验证。
