# 系统角色与权限

关联任务：[W2-01 系统角色（#4）](https://github.com/NamingIsVeryVeryHard/InnoGrad/issues/4)。

**状态：需求草案，待业务评审。** 本文将[问题定义](problem_definition.md)中的用户细化为 Actor，供[功能树](feature_tree.md)和[功能需求](functional_requirements.md)引用。功能权限、数据范围与业务状态共同决定一次操作是否允许。

## 角色说明

| 编号 | Actor | 使用入口 | 目标与主要操作 | 数据范围 |
| --- | --- | --- | --- | --- |
| ACT-01 | 学生 | 学生端，简洁入口 | 查看适用的招生、机会或培养要求，准备与提交材料，处理整改，维护成果，查看进度、画像和成长建议 | 本人申请资料、档案、材料、培养记录及已向本人发布的反馈；具体内容随业务阶段开放 |
| ACT-02 | 导师 | 管理端，建设重点 | 查看负责学生的培养进展与证据，提供指导与成长评价，参与获分配的复核和帮扶；按额外授权接收材料或代办 | 有效指导关系内的学生及明确授权的任务；不因导师身份获得学院全部档案 |
| ACT-03 | 审核与培养管理人员 | 管理端，建设重点 | 按授权接收材料、核对规则和证据、复核意见、提出整改、确认结果；维护规则、组织审核，开展招生、评奖、匹配、监测、帮扶和资源管理 | 获分配任务及其必需材料，或被授权培养单位、学生群体、节点和活动范围；各项操作能力分别授予 |

学生统一为 ACT-01，申请与在读属于业务阶段。申请阶段没有在读课程、培养计划等记录时，相关功能显示“不适用”；录取后的档案关联须先核实身份。ACT-03 包含审核专家及学院、研究生管理人员，具体职责通过能力授权与任务分配表达。一个人可以具有多种角色；每次操作仍需检查有效授权和数据范围。

两端共同完成业务闭环：学生提交与补交，导师和审核管理人员复核、确认与归档，学生查看已发布反馈。管理端是建设重点，学生端围绕本人业务提供简洁入口。学生档案可以先于账号建立；获授权人员接收外部材料或代办时，保留来源、原提供者和实际操作者。

## 权限矩阵

下表是双端业务权限的拟定分配。表中“按授权”表示角色身份本身不足以执行操作，还需要对应能力和对象范围；“本人”“指导范围”“任务范围”“管理范围”均由服务端核验。

| 操作 | 学生 | 导师 | 审核与培养管理人员 |
| --- | --- | --- | --- |
| 查看适用规则、节点要求与机会条件 | 本人适用范围 | 指导范围 | 获授权的任务或管理范围 |
| 接收或上传材料、正式提交、补交整改 | 本人适用业务 | 接收与代办能力分别授权，记录来源和实际操作者 | 接收与代办能力分别授权，记录来源和实际操作者 |
| 提交前智能预审 | 本人适用业务 | 无默认入口 | 无默认入口 |
| 查看材料、初审意见及证据 | 本人及已发布反馈 | 指导范围且有对应查看权限 | 获授权的任务或管理范围且有对应查看权限 |
| 提交复核意见、提出整改 | 无 | 获分配复核任务并授权 | 获分配复核任务并授权 |
| 确认正式审核、资格或评选结果 | 无 | 另授确认权限 | 另授确认权限 |
| 创建审核任务、分配处理者 | 无 | 无默认权限 | 任务组织或分配权限及管理范围 |
| 编辑、发布或停用规则版本 | 无 | 可按授权提交建议 | 规则维护、发布能力分别授予；业务核对按授权参与 |
| 查看全周期档案和画像依据 | 本人可见部分；申请阶段仅适用资料 | 指导范围 | 获授权任务的必需部分，或有对应查看权限的管理范围 |
| 补充、核实或修正成果与成长评价 | 提交本人资料与反馈 | 指导范围内提供评价；核实能力另授 | 任务范围内提供评价；核实、更正能力另授并留痕 |
| 查看与跟踪帮扶记录 | 本人可见且适用的事项 | 获分配帮扶事项 | 获授权的帮扶事项或管理范围 |
| 组织招生筛选、评奖、匹配和资源参考 | 提交本人申请、查看已发布反馈 | 获授权参与 | 活动组织与参与能力分别授予，并限定范围 |
| 授予角色、调整数据范围、查看审计记录 | 无 | 无默认权限 | 分别取得授权管理或审计权限 |

ACT-03 的复核、任务组织、规则编辑、规则发布、授权管理、结果确认和审计查看是不同能力；仅获分配复核任务的人员没有其他能力的默认权限。模型与 Skill 配置由取得接入配置权限的人员维护，业务专家按授权参与评价逻辑核对。是否需要岗位分离、双人确认或回避规则，由培养单位确认后细化。未配置的能力默认拒绝。

## 数据与操作边界

1. 服务端在读取、修改、检索、统计、下载材料和启动智能体任务时检查身份、能力、对象范围与有效期。修改请求还检查记录状态和版本。只隐藏按钮不能构成权限控制。
2. 未发布的内部复核意见不因“材料属于本人”就向学生开放；学生端只展示已发布反馈。内部意见的具体发布范围待业务确认。
3. 复核意见与正式结论分别记录。确认者必须有相应业务、节点或活动的确认授权；AI 初审成功、导师提出意见或专家完成复核均不自动产生正式结论。
4. 补交与更正生成新版本或更正记录，保留原始提交和处理依据。学生不得修改成绩来源记录、专家意见或正式结论。
5. 调整指导关系、撤回专家分配或撤销授权后，后续访问与正在执行任务的结果保存需重新核验。已形成的处理记录保留实际处理人。
6. 跨学生统计和匹配使用经授权的数据字段。输出不得通过名单、数量、引用链接或错误提示泄露无权查看的对象。
7. 接收外部材料与反馈时，区分材料归属人、原始提供者和系统操作者；补交代办、反馈发布及正式确认分别检查权限。没有真实反馈或授权依据时，不补造学生回复、同意或签名。

## 系统协作方

| 编号 | 协作方 | 职责与边界 |
| --- | --- | --- |
| SYS-01 | Inno-Agent 及模型服务 | 接收服务端限定的数据与规则，辅助解析、检查和生成解释；返回结果经核验后保存为辅助意见，不具有人的角色或确认权 |
| SYS-02 | 已获批准的数据来源与通知渠道 | 可能提供课程、成果或消息能力；来源、字段、身份认证和接口可用性尚未确认，不作为当前已接通系统 |

系统自身的定时处理属于内部行为。SYS-01、SYS-02 在系统边界外协作时可作为系统 Actor 标注，具体接入以[平台边界](../software/platform_reuse.md)为准。

## 权限验收场景

| 场景 | 预期结果 | 关联功能 |
| --- | --- | --- |
| 管理人员接收学生的外部材料并代办提交，学生尚无系统账号 | 材料归属、原始来源和实际操作者分别保存；只有具备相应权限才能提交，不生成学生登录或确认记录 | FR-1.2、FR-4.1、FR-4.3 |
| 导师查看有效指导关系内学生，再查看其他学生 | 仅允许指导范围内且具有对应权限的内容 | FR-1.2、FR-6.4、FR-8.1 |
| ACT-03 仅有当前任务复核权限，尝试确认结果或创建其他任务 | 可记录复核意见；正式确认与任务组织请求被拒绝，状态与正式结论不变 | FR-5.2、FR-5.5、FR-5.8、FR-5.1 |
| ACT-03 具备任务组织权限，但未被授予规则发布权限 | 可组织范围内任务，发布规则被拒绝 | FR-2.2、FR-5.1 |
| 学生访问本人材料，随后将请求对象改为他人的材料 | 本人授权内容可见；他人对象被拒绝，响应不返回其内容或下载地址 | FR-1.2、FR-4.1 |
| 学生处于申请阶段，尚未建立在读培养记录 | 可准备本人申请；培养进度标为不适用，不访问或生成其他学生记录 | FR-11.2、FR-11.4 |
| 智能体返回“通过”，或材料内包含要求跳过权限检查的文字 | 结果作为待核验辅助意见；不改变确认权限，不生成正式结论 | FR-10.1、FR-10.3、FR-5.8 |
| 导师关系或专家分配被撤销，原会话继续请求资料 | 服务端重新检查并拒绝失效授权；已保存历史意见仍保留原处理人 | FR-1.1、FR-1.2 |

## 待确认事项

- 身份来源、申请人转为在读研究生时的身份核实与档案关联方式。
- 规则发布、复核、正式确认与授权管理的责任岗位，以及兼任、回避和会签要求。
- 学生可见的内部意见、画像评价、帮扶记录和更正反馈范围。
- 跨单位协作、导师变更、任务撤回、批量数据使用和代办行为的具体授权流程。

上述事项决定最终权限配置，需在实现相关流程前确认。
