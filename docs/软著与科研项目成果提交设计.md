# 软件著作权与科研项目阶段成果提交设计及等保三级符合性说明

> 对应需求：语雀《[整理-1118](https://www.yuque.com/lanjm/ygdlgt/utqa8odrvx21mv6g)》材料提交组（`jkt`），GitHub Issues [#25](https://github.com/NamingIsVeryVeryHard/InnoGrad/issues/25)（软件著作权）与 [#26](https://github.com/NamingIsVeryVeryHard/InnoGrad/issues/26)（科研项目阶段成果）。
>
> 安全基线：GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》第三级（以下简称“等保三级”）。

---

## 1. 功能定位与模块边界

本轮交付在 InnoGrad 现有不可变提交版本（`Submission` / `Version` / `File`）、权限范围（`Supervision` + `policy.py`）、异步审核与归档（`AIJob` / `Outbox` / `worker.py`）、事实画像（`portraits.py`）和成长观察（`growth.py`）底座之上，新增两类日常成果提交：

1. **软件著作权（`kind = "software_copyright"`，Issue #25）**：记录软件全称、版本号、著作权人、学生承担的开发工作及登记状态；**仅当登记状态为“已登记”时要求填写登记号、登记日期并提供登记证书或证明附件**；支持未登记/申请中先提交并归档阶段记录，后续获证后通过 `/api/v1/submissions/{id}/updates` 发起正常进展更新，原有效档案在更新通过前持续有效。
2. **科研项目阶段成果（`kind = "research_project"`，Issue #26）**：记录项目或课题名称、学生本人角色、本阶段完成的具体事项及完成时间；**支持按需关联实验报告、数据集、代码或原型，明确不将关联材料与附件设为必填**。

两类成果均支持被年度报告通过 `reference_ids` 引用（固定版本追溯，标注 `archived` / `unverified`），归档后自动写入 `PortraitSnapshot` 并映射到成长画像的「课题与贡献」「实践落地」观察方向（仅统计可追溯来源条数，不计算能力分或排名）。

## 2. 数据与字段契约

### 2.1 软件著作权表单（`kind = "software_copyright"`，Issue #25）

| 字段 key | 中文名称 | 类型 | 必填规则 | 边界校验与业务口径 |
| --- | --- | --- | --- | --- |
| `metadata_version` | 表单版本 | `int` | 自动写入 `1` | 若传入只允许 `1` |
| `software_name` | 软件全称 | `str` | **必填** | 去首尾空白非空，1–200 字符，禁止控制字符；同步写入 `title` |
| `version` | 版本号 | `str` | **必填** | 1–50 字符，正则白名单 `^[A-Za-z0-9][A-Za-z0-9._+-]{0,49}$`（如 `V1.0`） |
| `copyright_holders` | 著作权人 | `list[str]` | **必填** | 1–50 名（前端支持换行/中英文逗号/顿号分隔，后端规范化去重），每项 1–100 字符 |
| `development_work` | 学生承担的开发工作 | `str` | **必填** | 非空，1–4000 字符，说明本人具体承担的设计、编码、测试等工作 |
| `registration_status` | 登记状态 | `str`（枚举） | **必填** | 仅允许 `unregistered`（未登记）、`applying`（申请登记中）、`registered`（已登记） |
| `registration_number` | 登记号 | `str` | **条件必填**：仅 `registered` 时必填；其他状态必须为空 | 4–64 字符，允许中英文/数字/`-`/`/`/`.`/`_`（兼容 `2026SR1234567` 与 `软著登字第...号`）；非已登记填值返回 `422` |
| `registration_date` | 登记日期 | `str` | **条件必填**：仅 `registered` 时必填；其他状态必须为空 | 严格 ISO 日期 `YYYY-MM-DD`，年份范围 `1970—2100`；非已登记填值返回 `422` |
| `period` | 所属学年 / 周期 | `str` | 选填 | 0–40 字符；填写后自动写入快照 `period` 供画像按学年筛选 |
| `software_copyright_key` | 规范化去重键 | `str`（只读） | 服务端自动生成 | 64 位 SHA-256 摘要，基于 `(software_name, version, copyright_holders, registration_number)` |

**附件材料类型白名单（`file_roles`）**：
- `copyright_certificate`（软件著作权登记证书）
- `registration_application`（登记申请或受理证明）
- `source_code_doc`（源代码或设计说明书）
- `development_proof`（个人开发工作证明）
- `other_proof`（其他证明材料）
- 附件要求：`registration_status == "registered"` 时至少提供 1 份证明附件；`unregistered` / `applying` 允许 0 份或多份附件。

- **虚构填写示例（已登记）**：见 [valid-software-registered.json](../fixtures/software-project-submissions/valid-software-registered.json)。
- **虚构填写示例（申请中 / 未登记）**：见 [valid-software-unregistered.json](../fixtures/software-project-submissions/valid-software-unregistered.json)。

### 2.2 科研项目阶段成果表单（`kind = "research_project"`，Issue #26）

| 字段 key | 中文名称 | 类型 | 必填规则 | 边界校验与业务口径 |
| --- | --- | --- | --- | --- |
| `metadata_version` | 表单版本 | `int` | 自动写入 `1` | 若传入只允许 `1` |
| `project_name` | 项目或课题名称 | `str` | **必填** | 去首尾空白非空，1–200 字符，禁止控制字符；同步写入 `title` |
| `student_role` | 学生本人角色 | `str`（枚举） | **必填** | 仅允许 `lead`（项目/子课题负责人）、`core_member`（核心成员）、`participant`（参与成员）、`other`（其他） |
| `role_description` | 角色补充说明 | `str` | **条件必填**：`student_role == "other"` 时必填；其他角色选填 | 0–100 字符（`other` 时 1–100 字符） |
| `stage_deliverables` | 本阶段完成的具体事项 | `str` | **必填** | 非空，1–4000 字符 |
| `completion_date` | 完成时间 | `str` | **必填** | 严格 ISO 日期 `YYYY-MM-DD`，年份范围 `1970—2100` |
| `linked_artifacts` | 关联材料列表 | `list[object]` | **选填（默认 `[]`，不设为必填）** | 最多 20 项；支持按需关联以下 4 类材料 |
| `period` | 所属学年 / 周期 | `str` | 选填 | 0–40 字符；写入快照 `period` 供画像按学年筛选 |
| `research_project_key` | 规范化去重键 | `str`（只读） | 服务端自动生成 | 64 位 SHA-256 摘要，基于 `(project_name, student_role, completion_date, stage_deliverables)` |

**`linked_artifacts[]` 单项结构**：

| 字段 key | 中文名称 | 必填规则 | 校验规则 |
| --- | --- | --- | --- |
| `artifact_type` | 材料类别 | 条目内必填 | 枚举白名单：`experiment_report`（实验报告）、`dataset`（数据集）、`code`（代码）、`prototype`（原型） |
| `name` | 材料名称 | 条目内必填 | 1–200 字符，禁止控制字符 |
| `url` | 外部访问链接 | 选填 | 仅允许完整 `http://` 或 `https://` 地址，禁止内嵌账密凭据与 `javascript:`/`data:` 等协议，≤ 2000 字符 |
| `file_id` | 关联已上传附件 ID | 选填 | 必须属于**本次提交已上传的 `file_ids` 集合**，防跨提交/跨学生 IDOR |
| `description` | 简要说明 | 选填 | 0–500 字符 |

**附件材料类型白名单（`file_roles`）**：
- `experiment_report`（实验报告）、`dataset_doc`（数据集说明或清单）、`code_artifact`（代码文档或仓库说明）、`prototype_doc`（原型设计或演示材料）、`project_proof`（项目参与或结题证明）、`other_proof`（其他证明材料）。
- 附件要求：**非必填**（允许 0 份上传附件与空 `linked_artifacts` 正式提交）。

- **虚构填写示例（无关联材料极简提交）**：见 [valid-research-project-minimal.json](../fixtures/software-project-submissions/valid-research-project-minimal.json)。
- **虚构填写示例（四类关联材料完整提交）**：见 [valid-research-project-with-artifacts.json](../fixtures/software-project-submissions/valid-research-project-with-artifacts.json)。

| --- | --- | --- | --- | --- |
| D-08 | 8.1.4.2 e)f) | 服务端细粒度访问控制、防水平/垂直越权 | **已落实** | 所有新建/保存/上传/提交/下载/画像接口均在后端校验角色、资源归属与有效 `Supervision` 范围；`linked_artifacts[].file_id` 强校验属于当前提交 `file_ids`，阻断跨学生/跨提交 IDOR（见 `test_software_copyright.py`、`test_research_project.py`） |
