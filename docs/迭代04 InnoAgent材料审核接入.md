# 迭代 04 · InnoAgent 接入与材料审核

日期：2026-11-04。

本轮负责公共 InnoAgent 接入层和材料审核完整流程。运行输入来自当前提交版本、附件原文和冻结规则；`material-review` Skill 可以单独交付，不依赖外部设计文档。

## 1. 交付范围

| 范围 | 本分支交付 |
| --- | --- |
| 公共接入 | `AgentClient`、请求与结果契约、工作区和会话、排队、超时、重试、取消与清理 |
| 材料审核 | 审核包、论文和年度规则、Skill 调用、读取覆盖和原文证据校验、业务路由 |
| 材料审核前端 | 学生提交和补正、审核状态、原因、报告、证据原件入口、归档结果和机构异常队列 |
| 协作接口 | 画像与预警同事复用公共客户端，各自提供 Skill、输出模型与业务规则 |

画像和预警业务由对应负责人实现，总工作台的页面合并及视觉收口由整合负责人负责。Agent 接入基础由本分支维护。

## 2. 实现结构

```text
AgentClient / AgentTask / AgentExecution
├── 独立工作区和会话
├── 输入上传与 Skill 调用
├── HTTP / SSE 和结构化结果
├── 排队、超时、重试、取消
└── 会话及工作区清理

InnoAgentAdapter（材料审核）
├── ReviewPackage / ReviewWorkspace
├── material-review Skill
├── 冻结规则和原文证据校验
└── passed / correction / exception
```

公共接口及调用示例见 [InnoAgent 统一接入接口](InnoAgent统一接入接口.md)。公共层的输出可以是任意业务定义的 JSON 对象；材料审核适配器要求输出 `checks`。

本轮移除了额外的权限预检、权限 marker、项目 policy 和自定义 native 守卫。客户端沿用 InnoAgent 自身的工具配置，不需要本分支的 native 权限补丁。

## 3. 审核包和执行流程

审核入口接收完整的 `review_package`：

| 字段 | 内容 |
| --- | --- |
| `version_id` / `kind` | 本次提交版本及材料类别 |
| `student` / `form` | 申报人和本次表单 |
| `attachments` | 附件元数据、用途、原件哈希及带页码或段落位置的原文 |
| `requirements` | 当前版本冻结的材料要求和审核规则 |
| `references` | 本次引用成果的指定版本和认定状态 |
| `period` / `late` | 报告周期和逾期标记 |
| `limitations` | 上游解析限制 |

完整 schema 和审核要求随 [material-review Skill](../agent-skills/material-review/SKILL.md) 交付。学校未提供可直接调用的审核服务时，由本项目部署并管理 InnoAgent 实例，当前本机地址为 `http://127.0.0.1:3107`。

每次审核创建非临时工作区，上传以下文件，再创建会话运行 Skill：

- `review/package.json`：完整审核包；
- `review/manifest.json`：完整上下文、附件和文本视图清单；
- `review/sources/*.txt`：完整附件原文；
- `review/output-schema.json`：结构化结果 schema。

Agent 使用工具读取完整材料。后端不把材料拆成多次业务审核，也不汇总多个局部报告。首次结果未通过结构、读取覆盖、规则或证据校验时，在同一会话中反馈具体问题，最多修正一次。

确定性语义结论必须有本次原文证据。引文仅有空白或定位差异时，可以在同一文件中寻找唯一原文并记录恢复过程；文字改写、跨块拼接或无法唯一定位仍被拒绝。运行结束后清理会话和工作区。

历史快照缺少 `kind` 时，仅以论文状态字段识别论文；有标题的年度报告仍按年度报告处理。兼容转换不改写已冻结快照。

## 4. 规则和路由

保留 agy 提供的 `material-review-5`、`paper-v2` 与 `annual-v2` 校准，历史冻结版本继续使用原规则。本轮没有改写 Skill 内容。

| 结果 | 业务处理 |
| --- | --- |
| 阻断项通过 | 自动通过，进入归档并生成关联快照 |
| 阻断项不符合，或要求补正的不确定项 | 退回学生，说明具体补充或修改内容 |
| 提示项，或允许作为提示的不确定项 | 附提示通过，不进入机构复核 |
| 服务失败、报告或证据校验失败、版本或授权变化 | 进入当前材料的机构异常队列 |

`compliant` 项上的一般备注不阻断通过。年度任务未要求额外成果证明时，不因缺少这类证明拦截年报。缺少正文、录用证明或其他必需材料时，先退回学生补正。

`AIJob` 保存任务、重试、会话和清理信息；完成结果按最新任务、当前版本和执行令牌条件落库。旧任务、旧版本及取消任务不能覆盖当前材料。归档前再次核对业务条件，更正期间保留原有效档案。

## 5. 前端交互

材料审核前端位于 [app.js](../frontend/prototype/app.js)，入口为工作台中的“培养任务”“论文成果”和“Agent 审核”。

| 交互 | 行为 |
| --- | --- |
| 学生提交 | 填写表单、上传原件、选择每份附件用途，保存或正式提交 |
| 审核状态 | 展示排队、审核中、通过、需补正和异常；执行中的材料详情自动刷新 |
| 学生补正 | 展示具体原因，编辑后重新提交，创建新版本重新审核 |
| 自动归档 | 区分审核通过、归档处理中和已经归档，展示有效认定版本 |
| 审核报告 | 展示中文检查项、补正建议、提示和原文证据 |
| 原件入口 | 报告和证据均可打开原件，PDF 带证据页码 |
| 机构异常 | 只汇集当前待审核版本的异常，支持重新审核或记录机构处理意见 |

状态、规则、用途和错误均按业务文案展示。报告正文隐藏输入哈希、Skill、session、原始状态码和配置内容；原文引文保持原样。提示项明确标为“不影响通过”。

预置演示报告、仅完成基础检查的结果和真实内容审核分别说明。历史报告不会显示为当前机构待办。已归档材料保留原认定来源，不因查看历史结果重新改变状态。

## 6. 运行配置

配置模板见 [backend/.env.example](../backend/.env.example)。本机 `.env` 不提交，配置如下：

```dotenv
AI_MODE=innoagent
AI_BASE_URL=http://127.0.0.1:3107
AI_MODEL=ecnu/ecnu-qwen-flash
REVIEW_WORKFLOW=agent
INNOAGENT_SKILL=material-review
INNOAGENT_TIMEOUT_SECONDS=600
INNOAGENT_QUEUE_TIMEOUT_SECONDS=600
```

InnoAgent 的模型和供应商在其服务端配置。安装完整 Skill 目录后，启动 InnoAgent、API 和 Worker；修改后端或连接配置后重启 API 与 Worker。材料适配器复用公共客户端，由 `AIJob` 负责持久重试。

## 7. 交接状态

上轮材料校准记录包含九组真实来源输入：正常年度报告、正常论文、缺少计划、标题或日期错填、版权表误作录用证明、贡献不符、作者不匹配和 23 页长论文。原文与执行日志保存在本机 `fixtures/` 和 `runtime/`，不随代码提交。

本轮完成公共客户端抽取、权限预检移除和前端流程补齐。按当前要求，尚未在这版代码上运行测试、真实模型重跑或浏览器验收。上轮的测试数量和路由统计不作为本版本已验收的证明。

后续验收只保留核心自动检查，并通过实际操作确认“通过归档”“学生补正重提”“机构异常处理”三条流程。画像、预警和总工作台其他页面不在本次材料审核验收范围。
