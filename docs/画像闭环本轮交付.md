# 画像闭环本轮交付 · 2026-11-02

面向华东师范大学上海智能教育研究院的本地验收候选增量。以下为建议工程门槛，非学校批准标准、生产发布或最终全周期系统验收。

## 本轮实现

提交 → 原生文本解析/规则建议 → 人工复核 → 退回补正重交 → 归档 → 证据型画像。新增 `portrait_snapshots` 表、`app/portraits.py`、迁移 `8e3b091c2d40`、四项画像集成测试及前端材料详情中的来源展示。

归档和画像在同一短事务创建；异常一起回滚，待处理事件保留。每份归档唯一快照；读取仅选择当前有效档案，更正过程中保留旧记录，更正归档后切换。重复旧事件不能替换当前画像。归档来源包括材料版本、规则版本、人工决定、字段路径和附件哈希。没有独立画像异步作业，避免其迟到覆盖问题。

接口 `GET /api/v1/students/{student_id}/portrait`：学生本人、当前关系内导师和管理教师可访问；技术管理员和其他学生拒绝。每次服务端重新鉴权，响应 `Cache-Control: no-store`。事实为人工通过申报的字段，不等于逐字段独立核真；不生成推断、能力分或资格结论。计数为有效申报记录数，尚非成果主档去重数。

## 隔离启动与人工操作

本轮未启动服务、未改变原开发数据库或既有演示账户。维护者需演示时，进入 backend 后创建新临时目录，显式指定数据库和文件根：

```sh
DEMO_ROOT=$(mktemp -d /tmp/graduate-demo.XXXXXX)
export DATABASE_URL="sqlite:///$DEMO_ROOT/demo.db" FILE_ROOT="$DEMO_ROOT/files"
export PYTHON_DOTENV_DISABLED=1 AI_MODE=rules AI_BASE_URL='' AI_MODEL='' AI_API_KEY=''
../.venv/bin/alembic upgrade head
umask 077
../.venv/bin/python -m app.seed > "$DEMO_ROOT/demo-accounts.txt"
printf '临时环境目录：%s\n' "$DEMO_ROOT"
../.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

第二终端同样进入 backend，设置相同的 DEMO_ROOT 和上述 export，运行 `../.venv/bin/python -m app.worker`。端口已占用时选择其他本机端口，不停止已有服务。账户文件仅限临时演示，不提交版本库。

用 student1 提交明确标注“合成演示”的论文及专门构造的 PDF/DOCX；teacher 对照建议退回；学生补正重交；teacher 人工通过；Worker 归档后在材料详情查看证据型画像与来源。发起论文更新时旧画像保留，重新通过后显示新版本。用 student2/operator 请求该画像应拒绝；撤销导师关系后应拒绝。能力评价应为“待评价”。不使用真实学生材料。

## 兼容、回退及剩余门槛

新增迁移只增加表。旧档案不会自动重算，接口返回 pending_snapshot_count，页面提示待生成；历史回填需要单独设计与验证。回退优先恢复已保存的上一份代码并保留新增表，不在有业务数据时降级删表。本轮未建立 Git 提交、未推送、未部署。

演示放行：独立走通上述浏览器流程、保留版本和测试证据。试点放行：院方确认名册/角色/组织范围、规则版本、成果主档、材料使用与保留范围；完成目标环境权限及恢复验证。生产放行：业务签字、端到端、负载、安全、监控、实际 RPO/RTO、发布回退与运维培训齐备。无越权、历史覆盖、重复生效、数据丢失等阻断缺陷。

八维评分、独立证据抽取、跨年成长和全周期其他培养节点仍未由本批完成。模拟原型不计入真实业务完成量。任务应绑定负责人、版本、验收用例与证据，状态依次为开发中、待联调、待验收、完成。
