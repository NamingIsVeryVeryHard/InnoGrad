# InnoGrad · 品牌与 Agent 审核调整

日期：2026-11-02。

- 页面标题、导航、登录页、页脚和导出文件统一采用 InnoGrad。
- 机构名称为上海智能教育研究院。既有 teacher、manager 示例账号的显示名称同步更新，账号 ID、密码、角色和历史材料不变。
- 新增真实 Agent 审核队列接口 `/api/v1/review-queue`，按权限返回当前提交版本、最新任务状态与材料审核结果。
- 材料结果区分：未启动、执行失败、需补充证据、发现问题、检查完成待确认。规则模式历史结果不冒充 Agent 报告。
- 按用户明确选择，当前 `backend/.env` 设置 `AI_MODE=agent` 和 `REVIEW_WORKFLOW=agent`，接口与密钥保持空值；页面明确显示“待配置”。材料保存和历史档案查询不受影响，新材料不会伪造审核成功。
- Agent 执行材料解析、规则检查、证据审核与补正建议。审核通过后自动归档并更新学生画像，不再要求每项人工确认。仅异常、无法判断或执行失败转交机构处理。
- 通过判定由服务器执行：报告成功、规则和解析检查完整、全部原件有可核验证据、无异常或未知项，且任务仍是当前版本的最新有效任务。失败、取消、旧版本、规则历史和未配置都不会自动归档。
- 决定记录 actor_type=agent 和 ai_job_id，由独立不可登录的服务身份留痕；不会冒记为教师审核。归档和画像记录保留审核来源。
- 机构工作台提供“仅机构异常”筛选，管理教师或当前责任教师可核验通过或退回补正。

## 后续接入

在本机 `backend/.env` 配置 `AI_BASE_URL`，按服务要求配置 `AI_API_KEY`。独立 Agent 应实现现有 `POST /review` 契约；兼容 Chat Completions 的服务可使用 `AI_MODE=chat` 并填写 `AI_MODEL`。重启 API 与 Worker 后，在 Agent 审核页点击“启动 / 重试”。密钥不写入前端。

## 验证

52 项后端测试、6 项前端测试通过，迁移校验通过。测试环境显式隔离本地 Agent 地址和密钥，不访问真实服务。真实 Agent 调用尚未验证，因为用户选择了待配置。
